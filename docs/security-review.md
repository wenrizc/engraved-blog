## 修复

### 依赖

初次 `npm audit` 报告 15 个受影响依赖，其中 1 个严重、13 个高危、1 个低危。升级 Astro 至 7.4.2、Sharp 至 0.35.5，并更新检查工具、站点地图和传递依赖后，审查时报告为 0 个已知漏洞。

### 后台接口

- 校验 Host、Origin 和浏览器跨站请求信息，拒绝 DNS 重绑定与跨站写入。
- 写入接口只接受 JSON，阻止通过普通表单或 `text/plain` 发起修改。
- 增加禁止 MIME 类型嗅探、禁止缓存、禁止页面嵌入和不发送来源信息的响应头。
- SVG 上传转为 PNG，已有 SVG 响应使用沙箱策略；图片上传后自动清除 EXIF/XMP/IPTC 元数据。
- 保留 Markdown 预览清洗、路径边界检查、文件版本冲突检查和原子保存。

### 照片与草稿

34 张照片已清除隐私元数据，并逐张比较清理前后的解码像素，确认像素未改变。原图备份在仓库外的 `~/.local/share/engraved-blog-audit-*` 目录。

初筛曾因 JPEG 内出现类似 GPS 标签的字节序列而报警；进一步解析 TIFF/EXIF 目录后，34 张原图及历史中的 4 个照片对象均未发现 GPS 字段。首次发布前，原始历史备份到仓库外，并在发布分支中清理这 4 个历史照片对象的其他 EXIF 数据。清理保留提交内容与作者记录，相关提交哈希会变化。本地原始备份分支不应推送到公开仓库。

发现并修复了草稿照片原图仍被 Astro 带入公开产物的问题：草稿照片在图片导入处理前移除图片字段。草稿 Markdown 文件仍由本地后台直接读取，网站构建不输出这些草稿的详情页和独有图片资产。

## 发布边界

- 这些检查表示审查范围内未发现泄露或已知依赖漏洞，不能代替后续持续扫描。
- 后台没有登录认证；同源防护不能阻止可信局域网内的其他设备直接调用接口。仅部署静态产物，不要把后台通过公网代理或端口映射公开。
- `draft: true` 控制网站可见性；公开 GitHub 仓库仍会公开草稿源文件，以及已经进入历史的内容。秘密和私人原始文件应保存在仓库外。
- 正式构建需设置 `SITE_URL` 为最终域名。GitHub Pages 工作流使用 `https://wenrihotel.com`，发布方式见根目录 README。
